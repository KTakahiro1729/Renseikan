# 連星館 HTMLテストプレイ v0.2

GM1人・PL5人のブラウザ試作。静的HTML/JavaScript/CSSで動作し、外部の実行時ライブラリは不要です。

## Cloudflare Pagesへ展開

Cloudflare PagesでこのGitHubリポジトリを選択し、以下を設定します。

| 設定 | 値 |
|---|---|
| Framework preset | None |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | リポジトリ直下（空欄） |

`wrangler.toml` にも `pages_build_output_dir = "./dist"` を指定しています。ビルドはJSONを検証し、公開ファイルだけを `dist/` にコピーします。テスト、Git履歴、READMEは配布しません。

ローカルで `npm run build` を実行し、生成した `dist/` をPagesのDirect Uploadでアップロードする方法も使えます。実際のCloudflareへのデプロイは別操作です。

公式資料: https://developers.cloudflare.com/pages/framework-guides/deploy-anything/

**配信と通信は別です。** この版の通信はBroadcastChannelで、同じ端末・同じブラウザプロファイル・同じオリジンのタブ間だけで動きます。公開URLを別端末で開いても接続しません。WebRTC/P2Pは未実装です。Discordは手動の音声通話にのみ使用し、API/Webhookは使いません。

## ローカル起動と検証

Node.js 22以上、HTTP配信にはPython 3を利用できます。

```sh
npm run check
python -m http.server 8000 --directory dist
```

`http://localhost:8000/` を開きます。GM卓で予定・装置を確定し、5席のPLタブを開いて夜を開始してください。GMが移動確定・ターン終了・朝の進行・投票集計を操作します。3分の時間管理はGMが行います。

## ゲームデータの編集

**編集元は `data/game.json` です。** 配列の位置で意味が変わる形式をやめ、名前付きの項目にしています。たとえば宝石の配置と価値は以下の項目です。

```json
{
  "id": "jewel",
  "name": "高価な宝石",
  "kind": "宝石",
  "room": "倉庫",
  "value": 4,
  "lang": "日本語",
  "text": ""
}
```

| 項目 | 編集内容 |
|---|---|
| `rooms` | 部屋名・階・説明 |
| `characters` | 名前・説明・外国語能力・関係対象候補 |
| `items` | 物品の名前、配置、価値、言語、本文、使用前／使用後／工作後の描写 |
| `initialItems` | キャラクターの初期所持品 |
| `tasks` | タスク条件の種類、表示文、点数、枚数 `copies` |
| `schedule` | 主人の初期行動予定。8枠中4枠が主人室 |
| `costs` | アクションごとのAP |
| `rules` | 配点、共同読書・混入などの暫定費用 |
| `rankings` | 囲碁・ビリヤードの強さ。`guide` は心得本所持者 |
| `mainCards` | メインカードの説明 |
| `explorationTarget` | 探究型の指定物品ID |
| `provisional` | 未確定箇所に採用したテスト用条件 |

毒草の `effect` は `A` / `B` / `C`、解毒剤は `antidote`、睡眠ハーブは `sleep`。毒C原料には `component: "a"` または `"b"` を指定します。名前を変更しても効能は変わりません。`entertainment: true` の書籍が娯楽本です。

値を変更後、`npm run check` で検証し、ビルドし直してください。配置・初期所持品・山札の変更は新規ゲームから反映されます。進行中の卓がある間はデータを更新しないでください。

`secret`、`diary`、`dict`、`forensic`、`sword`、`goGuide`、`billiardGuide`、`goBoard`、`billiardTable` などの既定IDはルールが参照します。表示名や本文は変更できますが、IDを変える場合はロジックも変更が必要です。新しい種類の行動はJSONの追加だけでは作れません。

価格目録の本文と `value` を整合させて編集してください。JSONは静的配信される公開定義です。セッションの秘密や参加鍵をJSONへ記入しないでください。

## ファイル構成

- `core.js`: 状態遷移・要求検証・証拠・得点・PL向けデータ生成
- `data/game.json`: 人が編集するゲーム定義
- `data-loader.js`: JSON読込・構造検証（ブラウザ／Node共通）
- `gm.js` / `player.js`: 画面と仮通信
- `scripts/build.mjs`: 配信用ファイル生成
- `test.mjs` / `rules.test.mjs`: 回帰テスト

## 今回の仕様対応

直近の変更指示を優先し、60分固定・大広間開始・主人室4/8・招待2回・主人の即時飲食・毒A/Cは吐瀉物なし／Bはありを採用しています。旧仕様書に残る共同寝室開始・可変ターン時間・主人室6/8は採用しません。

- 毒Cは対象ごとの摂取量と不均衡の開始を管理。均衡で予定を解除し、再不均衡で新しい2時間を開始。
- PCの毒発症、解毒、睡眠ハーブ、本人による飲食。提供された料理はPC本人が飲食するまで発症しない。
- 睡眠者の同室表示・調査・窃盗、女優の盗難特則。
- 清掃による血痕／吐瀉物除去と清掃前の証拠、物品の工作描写。
- 失敗したコマンド・進行操作は状態を変更しない。
- 鐘の認知者のみへ次の移動前に通知し、全員への鐘履歴送信を廃止。
- 日記を読んだ時の得点を目的変更前に判定。
- 殺害点は死亡時の目的型を保存し、GMが確定した真犯人へ最終精算で付与。
- 共同アクションは相手の承諾後に実行、AP分担、対局勝敗、主人との対局。
- 朝の議長による組分け、同じ会話グループへの証拠共有、遺体調査。
- 主人への招待の同室検証、暖炉調査、金品要求、各部屋の植物採取。

## 暫定・今後の範囲

配点、通常カード内容、共同読書、招待の対象予定枠の細部、毒の再摂取などは `provisional` に記載した条件です。一般物品の描写は初期文面であり、個別の推理に必要なシナリオ文章は今後の編集対象です。

時計操作・隠し通路等の将来拡張、死後に新たな傷を付ける操作、厳密な同時イベントの自動競合解決は未実装。真犯人の意図・誘導はGMが非公開申告とログを照合して確定します。仮面は目撃通知の名義変更が中心で、専用アイコンや完全な身元秘匿は未完了です。

同一オリジンではGMのlocalStorageや通信を参照できるため、本版は秘匿性を保証しません。P2P化時には認証と情報公開の境界を別途設計します。

保存形式はv2です。v1とは保存キーを分け、旧バックアップのインポートは拒否します。旧保存を自動削除しません。

## 2026-10-16 追加確定事項

`data/game.json` の `confirmed` に決定事項を記録しています。処理順は鐘→NPC移動→PC移動→PCアクション→毒発症→病死。毒はターン終了の経過時刻で判定し、睡眠回復を精算して次ターンへ進めます。

招待は未来の主人室予定を変更し、今いる主人を移動させません。朝は他人の所持品も調査できますが取得できません。他人が所持していない取得可能な物品は場所によらず取得できます。通常調査の実行履歴がなければ深い調査は不可です。共有された証拠だけでは通常調査済みになりません。遺体の二度目の清掃、物品の二度目の工作は拒否します。

確認待ち：毒の発症を終了境界へ対応させる解釈、鐘の操作時点で大広間にいないPCの扱い。これらは `provisional` に明記しています。
