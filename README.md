# 連星館 HTMLテストプレイ — GM/PLブラウザ v0.1

## 起動

Python 3 があれば外部ライブラリは不要。HTML/JSの分割ファイルなので、ダブルクリックの `file://` ではなくローカルHTTPサーバーで開く。

```bash
cd renjokan_browser
python -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開く。`GM卓へ` → GM画面で設定 → 各PCの「このPC画面を開く」で5個の別タブを開く → 夜を開始。

**重要：GMとPLのタブは同じ端末・同じブラウザプロファイル・同じオリジンで起動すること。** 異なるPC同士の通信はこの版にはない。

### 最短操作手順

1. `gm.html` で主人の8ターンの予定（主人室4枠）を設定し、装置のトリガー・追加条件・病死予定を設定する。
2. PC A～Eの「このPC画面を開く」を押して、5つのPLタブを開く。各PLには専用の鍵がある。
3. GMで「夜を開始」。各PLが行先・睡眠を提出する。
4. GMで「移動を確定して探索を開始」。各PLは自分の画面で調査・物品取得・読書・工作などを操作する。
5. GMが「探索終了・次ターンへ」。睡眠効率、毒の効果時刻などを処理し、次の移動へ進む。
6. T8終了後、朝5フェーズ。GMが個別行動→会話を進行し、PLは調査か2APの秘密通信を行う。
7. 最終投票（同数なら決選投票）。GMが履歴と申告を見て犯人・死因を確認し、「自動返還・最終採点」を押す。

## ファイル

- `index.html` : 起動案内
- `gm.html` / `gm.js` : GM画面、状態保存、進行、全履歴、投票集計、JSONバックアップ
- `player.html` / `player.js` : PC個別画面、秘密のメインカード、タスク、所持品、アクション、朝の調査とメッセージ
- `core.js` : ゲームルール・状態遷移・証拠・得点とGM→PL向けの個別表示データ
- `style.css` : スタイル
- `test.mjs` : コアのスモークテスト。`node test.mjs` で実行（Node.jsがある場合）

## アーキテクチャ

- GMが単一のゲーム状態を持ち、PLの操作要求を検証して更新する。
- PLへは `project(state, seat)` で生成した**本人用の投影データ**だけを送る。
- 通信は `BroadcastChannel` の同一オリジンタブ間の**仮アダプター**。P2PやCloudflareとは無関係。
- GMの `localStorage` に状態を逐次保存。ページ再読込後は同じGM卓を継続できる。
- GMからJSONをエクスポート・インポートできる。JSONには席の鍵と全秘密情報が含まれるので、GM以外へ配らない。
- PLタブはGMの開いた接続鍵つきURLを使う。同じタブを再読み込みしても再同期できる。
- 会話はDiscordを想定し、通話・ルーム制御などのAPI連携は一切ない。

### 保護に関する重要事項

**これは秘匿情報を安全に隔離した製品版ではない。** `BroadcastChannel` は同一オリジンから傍受でき、GMのlocalStorageも同一オリジンのスクリプトから参照可能。PL画面はUI上の秘密の誤表示を避けるため本人用の情報しか受信しないが、これをセキュリティ境界と見なしてはならない。異なる端末での実テストに進むには通信層の認証・秘匿性・ホスト権威を再設計する。

## 現段階で操作できること

- 5人のPC枠と公開キャラクター割当（異なる席のキャラクターと交換可能）
- 全員大広間開始、夜8ターン×60分、同一階移動と大広間経由の移動
- 主人の事前行動予定・招待2回・病死予定T7/T8。主人は同じ部屋に置かれた飲食物を消費
- 同室者の表示、寝室とソファー睡眠・妨害、朝の強制睡眠
- 夜15AP、朝追加10AP、未使用分の持越し
- 共通の通常タスク山札、メイン目的型、メインカードの交換と旧得点保持、達成補充、自主破棄1AP
- 読書（日本語1AP／外国語2AP）、キャラクターの言語能力と辞典、知識・読書履歴
- 物品の調査、取得、譲渡0AP、館内配置0AP、持ち出し者のリセット、最終投票による返還
- 守衛の主人予定と大広間記録、警鐘、対局、共同読書、料理、主人への飲食物提供
- 殺害・遠隔装置・一部の誘導処理、遺体調査と隠匿・移送、工作痕跡
- 毒A（1時間、吐瀉物なし）、毒B（2時間、吐瀉物あり）、毒C原料による遅延処理の試作、PC被毒時のAP−5（下限0）
- 非公開の殺害申告、朝の一方的な私信2AP、投票と決選投票、犯人と死亡原因のGM最終確認
- GM全イベントログと終了時のタスク点・推理点（別枠）

## 試作上の仮定と未実装の範囲

- メインカードの具体的な配点、通常タスクの100枚、価値表などは試作用の仮値。カードの完全な条件設定は今後のデータ化が必要。
- 主人の「招待」は、同室で誘い、指定した場所へ即時移動し、残りの在室予定枠を先頭から1枠消費するという暫定実装。
- 時間操作トリック、隠し部屋・部屋交換・隠し通路は未実装。
- 時計の表示改変、細かい同時刻の死因優先・複数犯人、毒Cの複数摂取・均衡回復・解毒剤などは完全には実装していない。
- 共同アクションは相手の確認クリックを要求せず、同室の相手を指定して実行する暫定仕様。
- 「どのアクションを同室者へ伝えるか」の通知粒度は暫定。防犯上の秘匿や変装も完全ではない。
- 朝の調査は現地・所持品を中心とした暫定画面。全館のカード調査・情報共有の詳細化が必要。
- 遺体の死後損傷の詳細判定、身元隠蔽、全ての殺害痕跡の精密な描写は未完了。
- WebRTC、Cloudflare、Discord API、認証サーバー、複数端末通信は実装していない。
- データ配布／カード説明や数値をGMがGUIから自由に編集する機能は未実装。現状は `core.js` を編集する。

## テスト状況

- `node --check` でJSファイルの構文確認済み。
- `node test.mjs` でコアの移動・夜→朝→投票・得点と毒A/Bの境界動作を確認済み。
- ブラウザを自動操作する試験は、実行環境の管理制限でページ遷移がブロックされたため**未確認**。GM/PL両画面のDOM・実際の複数タブ通信は、利用者のブラウザでの初回確認が必要。
